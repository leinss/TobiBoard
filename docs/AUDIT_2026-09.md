# TobiBoard audit — 2026-09 (wave W7-A)

Version audited: **6.8.16 / versionCode 6816**, `targetSdk 36`, commit `b6054ffaa`.
Scope: the fork delta (voice input, AI text fix, clipboard manager, model download,
the fork's settings screens). Inherited AOSP/OpenBoard/HeliBoard keyboard internals
are out of scope except where the fork modified them.

Method: a first-run walk on a clean install on an API 34 emulator
(`tobiboard_pixel6_api34`, serial `emulator-5556`), plus six read-only static audit
passes over the repo. Screenshots in `docs/audit-shots/2026-09/`.

Severity: **critical** = IME unusable, flow blocked, data leaves the device
unexpectedly, crash, security. **important** = hesitation, silent failure, clipped
or overlapping UI, wrong copy, unexplained wait. **minor** = polish.

### Top criticals

1. **U-1 / S-2** Voice input starts recording inside a password field, reproduced on device. The toolbar hides the mic and shows the incognito badge; the long-press-Return popup still offers it. With a cloud provider selected the audio is uploaded.
2. **S-1** Text fix can kill the keyboard process: `catch (Exception)` on the MediaPipe path does not catch the `OutOfMemoryError`/`UnsatisfiedLinkError` a ~1 GB native allocation can raise.
3. **S-3** A Keystore failure silently writes clipboard clips in plaintext with `ENCRYPTED = 0` and no user signal, contradicting the store claim.
4. **S-4** An on-device transcription commits into whatever field is focused when it finishes; the commit path carries no editor-session identity.
5. **S-5 / S-6 / S-7** The release pipeline is broken three ways: the signed-release workflow has failed on 100% of pushes to main, the F-Droid index workflow fails on every `release` event, and `make check` fails in a fresh clone.

Every settings screen was mapped statically and the root was walked on device.

- **Settings root, this build, in order**: Languages & Layouts, Preferences, Appearance, Toolbar, Voice, Text Fix, On-device models, Text correction, Secondary layouts, Dictionaries, Advanced, About (12 entries). Gesture typing and Gesture data are absent because the gesture library is not present in this build and `ENABLE_GESTURE_DATA_GATHERING` is off outside debug.
- **Unreachable**: `SettingsDestination.DataReview` ("data_review") is declared at `SettingsNavHost.kt:190` but its `composable(...)` block is commented out at `:118-121` and no `ReviewScreen.kt` exists. The only caller is also commented out (`GestureDataScreen.kt:433-441`). Navigating to it would throw. Inherited from HeliBoard's unfinished passive-gathering work.
- **Reachable only by a non-obvious gesture**: **DebugScreen** needs About → tap the Version row **five times** → back → Advanced → "Debug settings" (`AboutScreen.kt:78-93`, `AdvancedScreen.kt:87-88`). **ColorsScreen** is reachable only through a small pencil icon inside the theme-picker dialog (`ColorThemePickerDialog.kt:235`), and its title is an unlabelled editable text field, so the screen has no visible name.
- **Not in the nav graph**: `WelcomeWizard` is rendered above the NavHost by `SettingsActivity.kt:99-122` and only on first run.
- **Toolbar actions**: 31 `ToolbarKey` values. 11 are in the main toolbar by default, 10 in the clipboard toolbar, the rest must be added by the user in Settings → Toolbar. The fork added `ADD_TO_DICTIONARY` and removed `DPAD`, `FLOATING`, `BACKGROUND_GATHERING`. **Text fix has no `ToolbarKey` entry and cannot be added to the toolbar** (U-12). All 31 key names resolve to a string; none is missing.

### Host load and emulator notes

Load was recorded throughout, per the constraint. It started at **96**, peaked at **157** mid-walk from work outside this task, and the walk only proceeded in the windows where it fell below 40 (measured: 18.6, 24.1, 34.9). Two spells of waiting were needed. The load spike starved the emulator badly enough that `adb shell` calls timed out for minutes and SystemUI ANR'd twice; both ANRs were host contention, **not** app behaviour, and are excluded from the findings. The API 34 AVD (`tobiboard_pixel6_api34`) rendered the IME correctly throughout, which is the reason the API 36 `Pixel9ProXL` AVD was avoided — see the CLAUDE.md finding of 2026-08-31.
